## Findings

### [BUG] experiments/checkpoint-trajectory/run.py:49-85,1172-1177,1470-1471 — Executed imports precede the certified source snapshot

The driver imports `scripts.eval`, `scripts.train`, and every pipeline module before `main()` calls `snapshot_sources()`. If source version A is imported, its pathname is atomically replaced with stable version B, and the start/end checks both see B, the experiment executes A while its artifact certifies B. The exact final-model replay catches many training-critical substitutions, but it does not bind evaluation-only code such as `smooth_posteriors`, nor does it prove which version of the already-loaded experiment driver evaluated the snapshots.

Capture and stage an immutable source tree in a minimal bootstrap before importing pipeline code, then execute from that staged tree. Alternatively bind hashes of the actual loaded module/code bytes. Add an import-A/swap-to-B regression in which only evaluation logic differs.

### [METHOD] experiments/checkpoint-trajectory/run.py:438-492 — Raw switch scoring accepts any historical source run

`raw_switch_event` marks its source precondition true if *any* stable source run confirmed before the boundary. It does not require the source to be the state active at the boundary, the last stable run before the boundary, or chronologically adjacent to the target transition. A direct probe with stable source at 0.0-0.5 s, stable third-language output at 1.0-2.0 s, a 2.0 s reference boundary, and stable target at 2.5-3.0 s returned `detected=true`, 500 ms first-stable lag, and 1,000 ms confirmed lag even though the system had already left the source language.

This does not change the current result because both stored selected/final traces fail the source precondition and score 0/2. It can, however, change a future shortlist because raw switch recall is the first selector key. Require a source run that is active at the boundary or ends within a declared source-to-target collar, reject intervening states, and match the next eligible target run one-to-one. Reuse the chronology-safe scorer specified by the accompanying memo.

### [METHOD] experiments/checkpoint-trajectory/run.py:1047-1133 and REPORT.md:58-114 — Relative gates call a collapsed checkpoint useful

The `useful_change` gate requires only an earlier step, a two-point relative label gain *or* switch gain, and a committed-false-switch count no worse than the final model. Step 970 therefore passes on a 4.76-point composite gain, which is exactly three additional correct outcomes among the 63 selected 1 s/2 s/full decisions. Yet every one of the 161 trajectory states has zero minimum-language recall; selected and final detect 0/2 switches and have zero source preconditions; both commit 14 false switches in 78.97 seconds (638.22/hour); and selected accuracy is 8/21 rather than 15/21 on exact familiar controls and 45/70 rather than 55/70 on training clips.

The report discloses these failures and correctly says not to replace the main checkpoint, but `Verdict: adopt` plus “advance step 970” still conflates adopting the trajectory infrastructure with establishing a useful model candidate. Require absolute gates before external validation: nonzero recall for every class (and a predeclared macro floor), an exact-training/familiar-fit floor, a maximum false-switch rate, and enough valid source-conditioned switch events to evaluate the switch criterion. If those fail, retain the infrastructure while marking model selection inconclusive/reject rather than spending a locked validation gate on a collapsed candidate.

### [METHOD] experiments/checkpoint-trajectory/run.py:1010-1067 — The worst-language guard is computed only inside a shortlist that omits its optimizer

The shortlist includes best label composite, best raw switch, lowest development KD, final, and midpoint, but not the checkpoint with best minimum-language recall. `best_minimum_recall` is then computed only over those shortlisted rows. A globally more balanced checkpoint can therefore be excluded before the five-point worst-language guard is applied, and the guard becomes vacuous whenever the unrelated shortlist entries all collapse.

All 161 states happen to have minimum-language recall zero in this run, so this defect does not reverse the selected step. For the reusable selector, either add global best minimum recall as a shortlist category and compare against the global maximum, or apply the balance eligibility test to every state before constructing the at-most-five external-validation shortlist.

### [MINOR] research/crossed_voice_profile_diversification.md:19 — The mutual-information percentage labels the reduction as though it were the remainder

The stated 1.5596-bit value is correct, but it is 55.56% of the original 2.80735 bits. The parenthetical `44.44%` is the percentage reduction, not the percentage remaining after “reduces ... to.” Write “a 44.44% reduction (55.56% remaining)” to remove the ambiguity.

### [DEFEND] experiments/checkpoint-trajectory/REPORT.md:21-26,78-114 — The three-decision gain is adaptively selected from 161 states on a tiny reused development set

The experiment inspects 161 checkpoints on the same 21 repeatedly consulted synthetic clips, then reports a late-utterance difference of only three full-clip decisions. The report is candid about this and preserves external data, which keeps it useful as a diagnostic. In review, be prepared to defend that the scoring rule, shortlist, and thresholds were fixed before inspecting the trajectory, that no additional tuning will revisit these 21 clips, and that any external validation evaluates one frozen decision rather than launching another search.

## Interview questions

1. **What did schema 4 add beyond the availability ledger?** It binds the probabilities actually consumed in training to raw anchors, temperature-derived soft anchors, and the declared dense expansion, so a valid ledger cannot mask future-interpolated targets.
2. **Why is “a stable source existed before the boundary” not a valid switch precondition?** Because the system may have left that source for a third state long before the reference transition. The source must be current at the boundary or connected to the target by an explicitly collared transition.
3. **Why is step 970 not established as a useful checkpoint despite clearing the predeclared gate?** Its relative gain is three selected decisions against an already poor final model, while absolute class coverage, switch evidence, false-switch rate, training fit, and familiar-control fit all fail.
4. **How should the selector preserve language balance?** Apply an absolute/global minimum-recall eligibility rule before shortlisting, or explicitly include the globally best minimum-recall checkpoint and compare every candidate with that global value.
5. **How can start/end source hashes agree while the experiment executed different code?** Modules can be imported from A before the start snapshot, then their files can become stable B. Both snapshots see B while Python continues executing A already loaded in memory.
6. **What does the voice mutual-information calculation establish?** It proves an exact manifest assignment confound, not acoustic causality. The crossed experiment is needed to test whether removing that assignment improves language behavior.
