## Findings

### [BUG] src/streaming_lid/data.py:308-364,571-637 — Availability validation certifies a ledger, not the stored dense probabilities

`_validate_local_target_availability` recomputes valid source-sample bounds from `anchor_frames` and the declared expansion policy, but it never compares `teacher_probs` or `teacher_soft_targets` with the probabilities implied by `anchor_probs`. A target file can therefore declare a valid previous-anchor-hold ledger while storing a future-looking interpolation or any other same-shaped dense target.

I constructed a temporary cache entry with a valid previous-hold ledger/config, replaced the dense probabilities with linear interpolation, and updated every file/metadata hash. The production loader accepted it. At the probed middle frame the stored vector was `[0.475, 0.475]`, while the declared previous-hold vector was `[0.94, 0.01]`. Thus the README statements that the loader validates sample-level availability are stronger than the actual contract. The submitted cache itself is correct; this is a validator gap that permits a future invalid cache to pass.

Reconstruct `teacher_probs` from `anchor_frames`/`anchor_probs` under the declared expansion and compare exactly or within a specified serialization tolerance. Validate soft targets against normalized `anchor_probs ** (1 / T)` under the same expansion, or store soft anchors explicitly. Add this ledger/data-divergence probe as a regression test.

### [BUG] scripts/eval.py:66-98 and experiment callers — Concatenated stable logits are regrouped on the input-chunk clock

`streaming_forward` emits 12 stable frames for the first 16-frame input chunk because four frames are retained for lookahead, then emits later stable frames in a different phase. `streaming_output_groups` concatenates those outputs and slices the resulting output array into groups of 16. Those groups no longer correspond to the actual `streaming_step` calls or their availability timestamps. The new telephony, cross-view, and voice-factorial evaluations all inherit this reconstruction.

On the final checkpoint and `switch_hi_en_eval`, 798 input features produced 794 stable outputs and 773 alignment-valid outputs across 49 reconstructed groups. Comparing reconstructed timestamps with timestamps from the actual calls gave 571 frames at +40 ms, 188 at -120 ms, four at -100 ms, and only ten at zero. The first trained group is directly available at 335 ms but reconstructed at 375 ms. Group posterior L1 error averages 0.18638 and reaches 0.47072. Both switch traces still miss, so the submitted headline is not reversed, but the policy timestamps and grouped posteriors are not faithful to the model execution.

Return emission groups and their availability times directly from each `streaming_step` invocation. Do not infer call boundaries after concatenation. Add a fake-ingress-clock test that compares every group, output index, and timestamp with an instrumented streaming loop.

### [BUG] scripts/train.py:18-44,211-232 and src/streaming_lid/run_identity.py:73-85 — The source snapshot occurs after the source has been imported

The trainer imports pipeline modules before `main` captures the launch snapshot. If source version A is imported, the files are atomically replaced by version B before snapshot capture, and B remains stable through the end check, training executes A while the checkpoint identity certifies B. Launch/end equality only proves that the path was stable after the late capture; it does not identify the module bytes already loaded into Python.

Execute from an immutable staged checkout/container, or use a minimal bootstrap that captures and locks the complete source snapshot before importing any pipeline module. The identity must bind the code object actually executed, not merely a later reread of its pathname. Add an import-then-swap regression.

### [BUG] scripts/train.py:216-232, src/streaming_lid/data.py:442-528, and src/streaming_lid/run_identity.py:242-258 — Corpus and target launch identities can come from different manifest generations

The outer launch capture reads the corpus manifest, while `TeacherTargetCache` independently rereads that path to validate target metadata. Nothing requires `corpus.manifest_records_sha256 == target_cache.identity.manifest_records_sha256`. Under an A/B/A atomic replacement schedule, the corpus can capture A, the target cache can validate against B, and the end check can see A again. A B release differing only in held-out records can therefore publish a checkpoint whose corpus and target identities are each valid but mutually inconsistent and which cannot be evaluated under A.

Read one immutable manifest snapshot and thread its parsed records and digest through both corpus and target-cache construction. Require explicit equality between the corpus and target manifest-record digests in the launch contract and checkpoint. Exercise the A/B/A schedule in a regression test.

### [BUG] experiments/telephony-robustness/run.py:1246-1267 and REPORT.md — The published reproduction command cannot consume the current or historical input bundle

The telephony harness hard-codes the historical schema-v1 checkpoint/run contract. The current default checkpoint is schema 2, and a direct execution of the published command reaches `ValueError: checkpoint schema version is missing or unsupported`. The report instead binds historical checkpoint `bb2a7e2aee1796845c1880f618b0b465e025ace3912d860e02b2a63ac6c962e8` and its historical target metadata, but those ignored/overwritten inputs are not preserved in a retrievable bundle.

The checked-in JSON and report are internally auditable, but the advertised command is not executable from the submitted repository. Preserve an immutable content-addressed input bundle or update the validator to the current schema and rerun. The new result must bind downloadable or checked-in input bytes, not just their unavailable hashes.

### [METHOD] experiments/telephony-robustness/run.py:657-687,775-864 — Seven-way robustness scores ignore how much native-teacher mass survives restriction

The harness stores `selected_mass` but computes its frame, clip, delta, and gate summaries only after renormalizing the seven selected languages. Across the 63 clean clips, selected mass has minimum 0.000461, median 0.992971, and mean 0.829160; 10/63 clips are below 0.5 and 4/63 are below 0.1. A channel can push almost all native-teacher probability outside the supported set without being penalized by the closed-set top-1/F1 score.

The report labels the metric closed set, so its arithmetic is not false, and the very large degradation still supports rejection. For a robustness decision, also report native 107-way top-1/coverage and selected-mass changes, gate on retained mass, or introduce an explicit unknown/rejection outcome.

### [METHOD] experiments/telephony-robustness/run.py:892-962 — The stable-event matcher can manufacture a switch without a pre-boundary source state

`stable_run` may begin at any interior point of an already-running target prediction. `stable_switch_event` then sets `detected=true` for a target run even when `source_armed=false`. A trace that predicts the target class continuously through the annotated boundary is therefore scored as a detected switch, despite containing no source-to-target transition.

All stored teacher events happen to be source-armed and their target runs begin after the boundary, so this does not reverse the tables. Require a chronologically adjacent, pre-boundary source run and match the actual start of a target run to the reference event. Reuse a single transition scorer across experiments and add all-target, early-target, wrong-source, and interior-run cases.

### [METHOD] experiments/cross-view-kd/run.py:452-499,903-925 — The switch gate passes when there are no matched switch events

Every condition and arm records 0/2 policy detections and zero teacher/source commits. Nevertheless, `not_additional_misses` is true for the cross-view arm because both arms miss equally, all declared gates pass, and the overall verdict is “adopt.” A non-inferiority comparison over zero evaluable transitions is vacuous, not switch evidence.

The report calls this gate mechanical, and the monolingual improvements independently justify continuing the augmentation recipe. Add `switch_gate_evaluable` with a predeclared minimum number of matched source/reference events; when it is false, make the full switch verdict inconclusive and report the mono adoption decision separately.

### [METHOD] experiments/cross-view-kd/run.py:695-763 — The two-arm design cannot attribute gains specifically to clean-view teacher targets

The comparison is clean-input/clean-target versus degraded-input/clean-target. It demonstrates the effect of the complete cross-view training recipe, but has no degraded-input/degraded-teacher-target arm. Thus it cannot distinguish benefit from clean targets from ordinary codec/noise augmentation or their interaction.

Add a matched-view degraded-teacher arm with the same initialization, batch order, optimizer updates, and degradation schedule. The current report mostly scopes its recommendation to adopting the combined recipe, but mechanistic claims that the gains come from clean-view distillation targets are unsupported by these two arms.

### [METHOD] experiments/cross-view-kd/run.py:655-689,734-750 — The causal filter delay is not applied to training-target coordinates

The causal FIR channel transform delays degraded audio by eight milliseconds. Training verifies only that clean and degraded feature counts agree, then reuses the clean target at the same frame index. Evaluation adjusts the boundary coordinate for the filter delay, but training does not map target availability through the transform. Schema-v3 previous-anchor hold has no spare margin at exact anchors, so a clean target may depend on samples eight milliseconds later than the degraded evidence available at that nominal time. The historical schema-v2 interpolation was already future-invalid.

The monolingual labels are constant and the reported absolute F1 gains are not likely to be reversed; switch-training validity is affected, and the switch measurements are null. Carry a sample-clock mapping with every transform, shift/hold/mask targets conservatively, and rerun the availability validator after transformation.

### [METHOD] experiments/voice-text-factorial/run.py:227-231,1160-1207 and REPORT.md — The verdict conflates a large voice-profile effect with failure to reach an arbitrary ceiling

The complete pairing shows a 50-point profile effect. Even when text is held to held-out texts, seen profiles score 61.90% versus 19.05% for unseen profiles, a 42.86-point difference. Exact familiar cells reach 71.43%, leaving a 28.57-point shortfall from the perfect/familiar ceiling and failing the predeclared 80% sufficiency gate. These numbers support two separate conclusions: voice profile is the largest measured factor, and voice familiarity alone is insufficient to reach the quality bar. Failing the latter does not show that voice is not a primary contributor.

The design also maps every “seen” voice to male and every “unseen” voice to female, so it measures these particular renderer/profile-plus-sex bundles, not general speaker familiarity. Split the gates and language accordingly: report the large profile effect, the failure of voice-only sufficiency, and the sex/profile confound. The action plan should diversify voices in parallel with target/model optimization instead of using the sufficiency failure to deprioritize it.

### [DEFEND] Experiment prefix padding should be disclosed or excluded from robustness summaries

The telephony harness pads 15/21 clean four-second requests; cross-view has padding in 60/84 four-second condition rows; and the voice-factorial cache has padding in 52/84 fresh four-second clips. The native teacher treats the zeros as input content, while the student averages features across the padded interval. Because the experiments use paired cells, their deltas remain informative, and the voice experiment's full-duration primary comparison is unaffected. Still, absolute teacher/student scores on padded prefixes are not clean estimates of speech robustness.

Record the true unpadded length, mask padded frames, or publish a natural-full-duration slice. At minimum, disclose the padding prevalence and keep absolute padded-prefix scores out of release gates.

## Interview questions

1. **Why is a valid availability ledger insufficient?** Because the ledger constrains declared anchors, while training consumes dense arrays. Unless those arrays are recomputed or compared with the ledger, a file can claim causal hold while storing future interpolation.
2. **Why can concatenating correct stable logits still produce wrong policy timing?** Concatenation preserves output order but erases which streaming call emitted each frame. Re-slicing by the input chunk size assigns outputs to the wrong ingress clock.
3. **How can launch and end source hashes agree while executed code differs?** Python may import A before the launch snapshot, then the path may change once to stable B. Both snapshots hash B while the process continues executing A already resident in memory.
4. **What does the cross-view experiment actually identify?** It identifies the combined effect of degraded-input training with clean targets. A degraded-target control is required to isolate the clean-target component.
5. **What follows from the voice factorial?** The measured profile bundle has a large effect, but it is neither sufficient for high accuracy nor separable from the particular profile/sex assignment. Those are distinct conclusions.
6. **Why does the telephony rejection remain defensible despite closed-set renormalization?** The paired degradation is large and consistent inside the supported set. What remains unknown is how much additional failure is hidden by probability mass moving outside that set, which would strengthen concern rather than rescue deployment.
