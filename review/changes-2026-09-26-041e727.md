## Findings

### [BUG] `experiments/loss-factorial/run.py:42-106,1044-1054,1445-1602` — The source identity is captured after imported code has already executed

The driver imports Torch/NumPy, executes the complete trajectory driver as a
module, and imports the project training/data/model/loss stack before
`source_snapshot_at_start = snapshot_sources()`. A source-A module can
therefore execute, its pathname can become source B before line 1044, and
stable B hashes at the start and end will publish `source_snapshot_unchanged`
even though A produced the computation. `SOURCE_FILES` also omits the executed
package `__init__.py` and does not bind imported module origins. The last source
check is at line 1456, before result construction, finite traversal,
serialization, and `os.replace` at line 1602.

The current on-disk files do match every stored source hash, so this is not
evidence that this particular run used different bytes. It is evidence that
the result's executed-source claim cannot establish that fact. Launch the
experiment through the same pre-import content-addressed staged child used by
the main train/eval entry points, cover the complete imported tree and module
origins/runtime, and perform the final live-path equality gate immediately
before publication.

### [BUG] `experiments/loss-factorial/run.py:1045-1059,1458-1463` — Reference hashes and loaded reference objects come from separate pathname reads

The code hashes the checkpoint and summary, then independently calls
`torch.load(path)` and `Path.read_text()`. At publication it hashes both paths
again. An A/B/A replacement sequence can make both hash checks certify bundle
A while frame-control parity, `reference_run_id`, and all downstream training
use internally consistent bundle B. The result would then bind A's file hashes
to B-derived states without raising.

Read each reference once into immutable bytes, hash those bytes, deserialize
the checkpoint from `io.BytesIO` and the summary from the captured text, and
retain that exact snapshot through the run. The existing internal model-hash
and run-ID equality checks should then operate on those same captured values.

### [METHOD] `experiments/loss-factorial/run.py:394-403,512-531,611-618`; `REPORT.md:50-56` — The reported hybrid/gated “effective target priors” ignore temperature-scaled gradients

The audit constructs the hybrid prior as the arithmetic target mixture
`0.5*q_T + 0.5*y` and gives every clip equal weight. That is not the effective
target of the implemented objective. With logits zero and `T=2`, the hybrid
bias gradient is

```text
0.5*T*(u - q_T) + 0.5*(u - y),
```

so its normalized soft/hard target weights are 2/3 and 1/3, not 1/2 and 1/2.
The mixed switch clip also receives unhalved pure KD. Recomputing directly from
the retained 71 clip means gives a zero-logit gradient-equivalent English mass
of 9.2432%, not the published 10.4861%. For the gate arm, KD clips have scale 2
while hard-CE clips have scale 1, yielding 9.1897%, not 11.7477%. Away from
uniform logits, `softmax(z/T)` and `softmax(z)` differ, so no single fixed prior
represents the combined gradient at all.

The frame-KD and equal-clip pure-KD priors remain meaningful, and the driver
also records actual initial output-bias gradients. Rename the hybrid/gate
values as nominal target constructions, use the gradient audit for claims
about optimization pressure, or define an explicitly stated
gradient-equivalent diagnostic at a specified logit reference.

### [METHOD] `experiments/loss-factorial/run.py:389-404`; `REPORT.md:95-100` — The two hard-label recipes do not isolate breadth of correction from mixing and gradient scale

The report concludes that broad hard-label regularization helped more than
correcting the four teacher errors and therefore that those errors are not the
sole collapse mechanism. But the hybrid arm applies a half-KD/half-CE blend to
all 70 monolingual clips, whereas the gate arm applies full KD to 66
monolingual/mixed clips and fully replaces KD with CE on four clips. Thus the
comparison simultaneously changes label scope, blending versus replacement,
and the per-clip gradient scale induced by `T^2` KD versus `T=1` CE. One seed's
different fit cannot identify which of those changes caused the difference or
rule out the four teacher errors as the initiating mechanism.

Describe this only as a comparison of the two complete recipes. To make the
mechanistic claim, cross label scope (all versus audited-error clips) with a
common KD/CE blend/replacement rule, normalize or report initial gradient
scales, and repeat seeds.

### [METHOD] `experiments/loss-factorial/run.py:915-984,1380-1401`; `REPORT.md:28-32,75-116` — A training-only eligibility gate emits `adopt` despite collapsed held-out and switch behavior

Eligibility requires nonzero recall on 70 training clips, 80% accuracy on
those clips, and 80% accuracy on a 21-clip subset of those same training
examples. It imposes no held-out absolute floor, no treatment-versus-control
non-inferiority gate, no stability bound, and no evaluable-switch requirement.
The dev data is used only to rank already eligible states.

The actual selected hybrid state illustrates the gap. Step 1,520 gets 61/70
training and 17/21 exact-Edge decisions, but Edge English is 0/3; held-out
English and Hindi recalls are zero at all three deadlines; minimum-language
composite is zero; it makes 13 false commits versus eight for matched frame KD;
both switch source preconditions and detections are 0/2; and switch no-collar
accuracy is 0%. A direct selector probe with the three training gates true,
development composite zero, and 999 false switches was still eligible and
selected. The report is commendably explicit that this is not a checkpoint
promotion, but the machine-readable verdict and “sole loss candidate” claim
are not guarded by evidence that the recipe repaired transfer or switching.

Use `inconclusive`/`diagnostic_follow_up` unless a treatment clears predeclared
absolute and control-relative held-out per-language, stability, and evaluable
switch gates. If the intention is only to nominate a training-fit recipe for a
new experiment, encode that separately from `adopt`.

### [METHOD] `experiments/loss-factorial/run.py:832-839,936-970`; `experiments/checkpoint-trajectory/run.py:438-492` — The selection tie-break inherits a chronology-unsafe raw switch event

`raw_switch_event` treats any stable source run confirmed anywhere before the
boundary as the source precondition; it does not require the source run to be
active immediately before the boundary. A trace
`source,source,source,third,third,target,target` at 0.5 s spacing with boundary
2.0 s falsely reports detection at 2.5 s/confirmation at 3.0 s even though the
third language, not the source, is active at the boundary. The factorial
selector then uses `raw_detected` as a tie-break.

All actual loss-factorial switch rows have zero raw detections, so the defect
did not choose step 1,520. Require the stable source run to cover or directly
abut the boundary and the target's stable run to be a chronological transition
from that source; do not rank on switch recall when the source precondition is
absent.

## Interview questions

1. **Why is a 50:50 KD/CE loss not a 50:50 effective target at `T=2`?**
   `T^2 KL(q_T || p_T)` has logit gradient `T(p_T-q_T)`, while CE has
   `p_1-y`; equal scalar loss weights therefore do not imply equal gradient
   weights.
2. **What does exact frame-control reproduction establish?** It strongly
   validates data order, initialization, optimizer, and the production KD arm
   under this runtime. It does not repair the driver's pre-import source or
   reference pathname race.
3. **What was actually learned about hybrid KD+CE?** It fit the familiar
   synthetic corpus better and was the only tested recipe to pass the local
   gates. Transfer remains unproved: worst-language held-out recall is zero,
   stability worsens versus the matched control, and neither switch is
   evaluable.
4. **Why does the error-gate failure not prove the four teacher errors are
   irrelevant?** Hybrid versus gate also changes mixture/replacement and
   gradient scale. A crossed, gradient-controlled ablation is needed for that
   causal attribution.
5. **What must be true before reporting switch lag?** The intended source must
   be stably active at the boundary, followed chronologically by a stable
   target transition. Here neither direction satisfies the source
   precondition, so lag is undefined.
6. **How should the candidate be frozen for external scoring?** Either retain
   the exact selected state under its recorded hash, or freeze the complete
   retraining and checkpoint-selection protocol before opening external data.
