## Findings

### [BUG] `experiments/hybrid-external-validation/run.py:90-149,1453-1460,1644-1648,1690-1731` — The published run ID can name source/runtime that did not execute

The historical main pipeline is usefully loaded from a validated immutable
stage, but the experiment itself is not. Python executes the live
`loss-factorial` driver (which in turn loads trajectory helpers) at lines
141--149. Only after every top-level import completes and `main()` begins does
line 1459 call `live_source_snapshot()`. The experiment module itself has also
already executed its top level by then. An A-to-B change between import and
that snapshot therefore produces predictions from in-memory A while the run
identity records stable on-disk B. The end comparison cannot detect that
history because both of its pathname reads see B.

The active runtime is recorded only in `results["environment"]` at lines
1725--1731, outside `experiment_identity` and hence outside `run_id`. On a copy
of the actual result, changing Python and Torch versions to arbitrary values
left the canonical identity and stored run ID exactly
`ea051d051708a1f461f689f5e9c6a4da86ba8f0b20e209aad67edefd06ac1a0a`.
The last live-source check also occurs before result construction and the
atomic write at line 1792, so `source unchanged at publication` is not actually
proved.

This is a provenance error, not evidence that the stored numeric rows are
wrong: I independently reproduced those rows. Launch a small parent that
captures and stages the driver, helper closure, package initializers,
project/lock files, and runtime before any project import; execute a child only
from that stage; include the active environment in the content-derived run
identity; and repeat stage/input verification immediately before the final
rename.

### [BUG] `experiments/hybrid-external-validation/run.py:1462-1484,1650-1658` — Reference hashes can bind generation A while deserialization consumes B

Checkpoint, summary, parent-loss result, prior-external result, and external
manifest hashes are read first at lines 1462--1468. The same paths are then
opened separately for JSON or `torch.load` at lines 1469--1484, and are hashed
again only after the expensive run. This is the same split hash/load contract
already found in the parent loss experiment.

A deterministic A/B/A probe following these exact operations produced:

```text
start_equals_end True
identity_names_A True
consumed_B True
```

Thus stable start/end hashes do not prove which bytes supplied the states,
metrics, or reference predictions. Read each artifact once into an immutable
byte snapshot, hash and parse/load that snapshot (`io.BytesIO` works for
`torch.load`), or copy all inputs into a content-addressed read-only stage
before computation. Final pathname rehashes may remain drift alarms but must
not be the binding mechanism.

### [BUG] `experiments/english-teacher-bakeoff/run.py:40-72,322-383,342-383,1558-1569,1578-1654,1687-1689` — The new bake-off verifies mutable source/model paths after execution has begun

The driver imports Torch, `scripts.teacher_targets`, and the local package at
lines 40--72, then captures `launch_source` only at line 1569. Its source table
omits at least the executed package initializer and project/lock files, does
not validate module origins, and runs directly from the editable worktree.
Consequently it can execute imported source A while certifying on-disk B.

Model artifacts have a parallel gap. `verify_snapshot()` hashes each file near
launch, but individual predictors later load those files again by pathname,
possibly minutes later and after earlier models have run. The final barrier
rehashes source and input audio only; it never rehashes the model snapshots.
An artifact can therefore be verified as A, consumed as B, and restored to A,
while a cached progress row and final run ID continue to name A. Progress-row
reuse makes this more than a narrow publication race. The last source/input
check also precedes output assembly and rename.

Use the same pre-import staged-child contract as the main pipeline and stage
or single-read every model/preprocessor artifact before loading. Include
`__init__.py`, all transitive local code, project/lock/runtime identity and
module origins, and put a final immutable-stage/input check immediately before
publication. The cutoff driver compiles, but it should not publish a final
report with the present provenance flags.

### [METHOD] `experiments/english-teacher-bakeoff/run.py:533-550,1154-1198,1329-1378,1443-1503` — Restricted-space gates can adopt a teacher that fails the target-quality contract

The driver correctly retains native winners, selected absolute probability,
conditional probability, and selected mass. None of the adoption gates uses
the native winner, selected mass, or absolute manifest-language probability.
Even `fix_at_least_3_of_4_ecapa_wrong_edge_english` means conditional
seven-way correctness. A candidate whose dominant native class is unsupported
and whose seven selected classes contain negligible mass can therefore pass
every listed quality check after renormalization.

This directly contradicts the new research protocol: the memo says the primary
screen must require native English and not merely English after deleting most
probability mass (`research/targeted_indian_english_teacher_audit.md:292-296`),
and the repaired main cache now requires at least 8/10 native winners plus
retained-mass and manifest-probability floors. Apply those same dimensions to
each candidate, including exact per-language floors, or label the output a
restricted-space diagnostic rather than a teacher-adoption verdict.

## Interview questions

1. **Why is hashing helper source after import insufficient?** Python executes
   and caches module A. If the path becomes B before hashing, later start/end
   hashes can both certify B even though all calls still execute A.
2. **Why do equal start/end artifact hashes not close an A/B/A race?** Hashing
   and deserialization are separate reads. The consumer may open B between two
   observations of A; identity must bind the same immutable bytes that are
   parsed.
3. **Why can selected-seven accuracy disagree with native teacher quality?**
   Renormalization deletes all unsupported classes. English may win the
   selected subset even when an unsupported native class dominates or the
   selected subset has negligible total mass.
4. **What does the hybrid external result actually establish?** For one seed,
   one 50:50 KD+CE recipe and an already-consulted FLEURS validation cohort, the
   selected hybrid regresses both matched controls and still collapses a class
   and misses switches. It does not show that all labelled supervision is bad.
5. **What can a successful English bake-off conclude before Svarah and a
   matched student?** At most that one frozen candidate should advance to
   independent Indian-English/all-language confirmation. It cannot yet justify
   a global teacher or deployed-student change.
6. **Why is the failed main quality floor still publishable?** It preserves an
   exactly reproducible failure baseline. The failure forbids balanced-target
   or promotion claims; it need not erase the diagnostic run.
