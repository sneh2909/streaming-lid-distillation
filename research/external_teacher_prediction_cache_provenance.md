# External-teacher prediction-cache provenance (BUG-18)

Research, web, and Hugging Face Hub audit: **2026-09-26
(Asia/Calcutta)**.

## Decision

The retained ECAPA cache is internally coherent, but the current artifact does
not prove which code and runtime produced it. Pinning the model checkpoint is
necessary but not sufficient: a prediction is generated by an activity that
also consumes the evaluator source, ordered language/index mapping, input
release, preprocessing and batching recipe, and numerical libraries.

The present cache binds the FLEURS manifest, model ID/revision/artifact, five
prefixes, a short-clip policy, and a name for the prediction space. Its reuse
path then checks only its own mutable payload hash, equality with that partial
identity, and ten vector lengths. The downstream run ID binds the *consumer's*
current source but neither the cache producer nor the accepted cache/prediction
digest. A current consumer therefore can report old predictions as if its own
source and environment created them.

Repair this as one lineage chain:

```text
staged producer + runtime + pinned model + ordered mapping + exact input release
                                  |
                                  v
                    raw ECAPA prediction artifact
                                  |
                                  v
                 recomputed summaries and experiment result
```

BUG-16 must establish the executed producer, BUG-17 must establish the exact
FLEURS input release, and BUG-18 must link both to the prediction artifact and
then link that artifact to the experiment run ID. These are complementary
contracts, not substitutes.

This work has **zero expected model or accuracy gain**. Exact parity with the
historical teacher controls is **unverified** until a fresh schema-2 pass is
run. The existing checkpoint-rejection verdict remains supported independently
by the student-only +0.38-point gain missing the predeclared +2-point gate,
zero worst-language composite, and two local switch misses.

## Exact current implementation

The producer in
[`evaluate_teacher()`](../experiments/checkpoint-external-validation/run.py#L654)
does the following:

- resolves and byte-verifies the pinned ECAPA snapshot;
- loads `EncoderClassifier` on CPU and derives the seven teacher indices;
- evaluates prefix order `full, 4, 2, 1, 0.5` seconds;
- uses batch sizes `2, 8, 16, 16, 16`, longest-first within a prefix;
- pads each batch and supplies the relative true lengths;
- selects the seven native log-posterior columns, conditionally normalizes
  them, and computes selected-language mass;
- retains only the winning project label and its conditional maximum for each
  example; and
- retains selected-mass **aggregates**, not per-example masses.

The schema-1 identity in
[`teacher_cache_identity()`](../experiments/checkpoint-external-validation/run.py#L752)
contains:

```text
schema, external manifest digest, model ID, model revision,
combined model-artifact digest, prefixes, short-clip policy, prediction-space name
```

It omits:

- the source stage or even the hashes of `evaluate_teacher()`,
  `label_indices()`, the audio loader, and imported initializers;
- the import-origin ledger needed to show those bytes were actually executed;
- Python, SpeechBrain, Torch, torchaudio, NumPy, and platform identity;
- `pyproject.toml` / `uv.lock` identity;
- `LANGUAGE_CODES` and its ordered map to teacher indices and label strings;
- sample rate, tensor dtype, prefix sample counts, prefix execution order,
  batch sizes/order, padding/`wav_lens` semantics, and inference mode;
- the exact ordered clip/audio identity rather than only the cache manifest's
  self-declared aggregate digest; and
- an independently named digest of the raw prediction payload.

The read path in
[`cached_or_fresh_teacher()`](../experiments/checkpoint-external-validation/run.py#L765)
trusts the cached `summary` and `teacher_identity` after checking the partial
identity and array lengths. It does not validate labels, null placement,
finiteness, probability ranges, prediction/max consistency, or agreement
between raw rows and summaries.

Finally,
[`experiment_identity`](../experiments/checkpoint-external-validation/run.py#L1278)
contains the current source snapshot and model artifact, but not the cache
digest, prediction digest, producer identity, or `environment`. The package
versions are written later as descriptive result fields. That means neither a
different self-consistent cache nor a different producer environment changes
the current run ID.

There are 700 slots at each of five prefixes. All 700 are eligible at 0.5, 1,
2, and full duration; 696 are eligible at 4 seconds and the other four have
paired null label/probability entries. In the current object:

- all 3,496 eligible labels are in `en/hi/mr/bn/ta/te/gu`;
- all 3,496 eligible maxima are finite and in `[0,1]`;
- the classification summary recomputes exactly from the stored winners and
  maxima after removing `retained_selected_mass`; and
- selected-mass aggregates exist for all five prefixes, but their underlying
  per-example values are absent and cannot be rederived.

The cache stores no seven-way vectors. Thus a validator cannot prove that the
declared maximum is the maximum of a normalized conditional posterior, that
the winner corresponds to its argmax, or that selected mass is the sum of the
seven native probabilities. This positive audit shows no current numerical
corruption; it does not establish producer lineage.

## Reproduced accepting case

I copied the live cache to a temporary directory, changed the first full-clip
prediction from `en` to `hi`, set its reported maximum to `0.999999`, replaced
the returned teacher revision with `forged-producer-revision`, deliberately
left the cached summary unchanged, and recomputed the cache's own canonical
hash. The production read function accepted it without loading a model:

```text
read_gate_accepted=true
changed_prediction=[en,hi]
returned_forged_teacher_revision=forged-producer-revision
cached_summary_stayed_unchanged=true
self_hash_changed=true
run_identity_contains_live_cache_digest=false
run_identity_contains_attack_cache_digest=false
recomputed_run_id=8ec024940fdd6f38731cc26f2d2f5a5ec962bdb9018d6f3a395f49b30a6097ea
stored_run_id=8ec024940fdd6f38731cc26f2d2f5a5ec962bdb9018d6f3a395f49b30a6097ea
```

This was a read-only probe: the checked cache/result were not edited, the
mutated copy lived under `/tmp`, no model was loaded, and Torch was limited to
six threads.

The case proves two separable defects:

1. the reuse gate does not validate the artifact's semantics or derivations;
2. the experiment identity does not bind the accepted prediction artifact.

It does not prove that the retained 70.24% ECAPA composite is wrong. The cache
was created shortly before publication and its current labels/probabilities
are well formed; the historical producer is merely not established by the
artifact.

## Why the Hub pin does not close the gap

The model side is already pinned well. A live
[Hugging Face Hub API query](https://huggingface.co/api/models/speechbrain/lang-id-voxlingua107-ecapa/revision/0253049ae131d6a4be1c4f0d8b0ff483a0f8c8e9)
on **2026-09-26** using the installed `huggingface-hub==0.24.7` resolved
[`speechbrain/lang-id-voxlingua107-ecapa`](https://huggingface.co/speechbrain/lang-id-voxlingua107-ecapa)
to full revision
[`0253049ae131d6a4be1c4f0d8b0ff483a0f8c8e9`](https://huggingface.co/speechbrain/lang-id-voxlingua107-ecapa/tree/0253049ae131d6a4be1c4f0d8b0ff483a0f8c8e9),
last modified **2024-11-27T20:12:38Z**, public/ungated, with Apache-2.0
metadata. The four consumed files still match the project's exact sizes and
hashes:

|---|---:|---|
| `classifier.ckpt` | 762,555 | `a50d9024ff58d317031c9787d4c6c614d454a87a8ef32f9d36338cd3ff57adbc` |

The official Hub 0.24.7 guide says downloads are version-aware, a specific
revision may be supplied, and a commit pin must use the full-length hash
([documentation accessed 2026-09-26](https://huggingface.co/docs/huggingface_hub/v0.24.7/en/guides/download#from-specific-version)).
This establishes the input model bytes. It says nothing about a project-owned
JSON generated later.

For the project order `en,hi,mr,bn,ta,te,gu`, the pinned label file gives
indices `20,35,63,9,91,92,31`. That ordering is behavior, not decorative
metadata: swapping columns changes every conditional prediction without
changing model bytes. The pinned
[`label_encoder.txt`](https://huggingface.co/speechbrain/lang-id-voxlingua107-ecapa/blob/0253049ae131d6a4be1c4f0d8b0ff483a0f8c8e9/label_encoder.txt)
must therefore be coupled to the exact project-language order in the producer
identity.

The same applies to the numerical stack. SpeechBrain's tagged v1.0.3
[`EncoderClassifier`](https://github.com/speechbrain/speechbrain/blob/v1.0.3/speechbrain/inference/classifiers.py#L137-L205)
uses the supplied relative lengths in feature normalization and the embedding
model, then returns classifier log posteriors. The project's conditional
seven-way transform is outside that library. Source, library, length/batching,
and transform identities all participate in the generated artifact.

## Primary provenance precedents

These sources support the shape of the contract; none is evidence that the
current cache already meets it.

- W3C PROV-DM, published **2013-04-30**, models an entity as generated by an
  activity that used other entities. A prediction cache is the entity;
  evaluator execution is the activity; source, data, model, mapping, and
  runtime are used entities
  ([W3C Recommendation](https://www.w3.org/TR/2013/REC-prov-dm-20130430/)).
- Google's ML Metadata guide, last updated **2024-09-06**, records every
  artifact used and produced by an execution and explicitly uses matching
  prior inputs to decide whether an output can be reused
  ([MLMD guide](https://www.tensorflow.org/tfx/guide/mlmd)).
- SLSA Build Provenance v1.2, current and accessed **2026-09-26**, separates
  the output subject, process definition/parameters, resolved dependencies,
  and run details. That is a useful schema precedent for this inference
  artifact, not a claim that this repository has a SLSA-certified builder
  ([v1.2 specification](https://slsa.dev/spec/v1.2/build-provenance)).
- SLSA also makes the trust boundary explicit: unsigned level-1 provenance
  helps prevent mistakes but is trivial to forge; tamper protection requires
  authenticated provenance from a trusted platform
  ([v1.2 build levels, accessed 2026-09-26](https://slsa.dev/spec/v1.2/build-track-basics)).

The last point prevents overclaiming. The proposed local schema closes stale
reuse, accidental mutation, and same-run attribution errors under this
repository's ordinary honest-filesystem threat model. It does **not** prove
authenticity against an attacker who can rewrite both cache and metadata.
Signed hosted provenance or independent recomputation would be needed for that
stronger claim; it is unnecessary for this take-home unless its threat model
changes.

## Proposed schema-2 producer contract

### 1. Define the producer before inference

Create one immutable `teacher_prediction_producer` inside BUG-16's staged
child, before the first teacher call. Hash its canonical form to
`producer_identity_sha256`. At minimum it should contain:

```json
{
  "schema_version": 2,
  "artifact_kind": "external_teacher_predictions",
  "executed_source": {
    "stage_root_sha256": "...",
    "module_origin_ledger_sha256": "..."
  },
  "runtime": {
    "python": "3.10.12",
    "platform": "...",
    "packages": {
      "speechbrain": "1.0.3",
      "torch": "2.6.0+cpu",
      "torchaudio": "2.6.0+cpu",
      "numpy": "2.2.6",
      "huggingface-hub": "0.24.7"
    },
    "pyproject_sha256": "d203d763...ce67",
    "uv_lock_sha256": "b1155aa9...b0c",
    "device": "cpu",
    "torch_intraop_threads": 6
  },
  "model": {
    "repo_id": "speechbrain/lang-id-voxlingua107-ecapa",
    "resolved_revision": "0253049a...e8e9",
    "artifact_sha256": "f193a054...f706",
    "files": "exact path/size/hash table"
  },
  "inputs": {
    "fleurs_release_lock_sha256": "BUG-17 value",
    "manifest_exact_sha256": "...",
    "manifest_records_sha256": "ef0ec364...637",
    "ordered_audio_set_sha256": "..."
  },
  "mapping": {
    "language_codes": ["en", "hi", "mr", "bn", "ta", "te", "gu"],
    "teacher_indices": [20, 35, 63, 9, 91, 92, 31],
    "teacher_label_file_sha256": "9f566d83...c17f",
    "ordered_teacher_labels": "exact seven strings"
  },
  "inference_recipe": {
    "sample_rate": 16000,
    "prefix_samples": ["full", 64000, 32000, 16000, 8000],
    "prefix_execution_order": ["full", "4", "2", "1", "0.5"],
    "batch_sizes": {"full": 2, "4": 8, "2": 16, "1": 16, "0.5": 16},
    "batch_order": "eligible_then_num_samples_descending",
    "lengths": "true_samples/padded_samples",
    "mode": "eval+torch.inference_mode",
    "transform": "exp selected log-posteriors; divide by selected mass",
    "output_schema": "ordered absolute selected probabilities, float semantics"
  }
}
```

Fields that can affect exact output should be bound even if they are expected
to be mathematically irrelevant. Batch partitioning, thread/backend choices,
and library builds can change floating-point reductions. Later evidence may
justify a narrower compatibility key; schema 2 should begin fail-closed.

Do not put cache path, creation timestamp, or wall time in the semantic
producer identity. They describe an invocation but do not define the
predictions. Record them in a separate observation envelope so a fresh
generation and a clean reuse can share one semantic identity.

### 2. Retain enough raw output to validate every derived claim

For every ordered `(clip_id, prefix)` request, store:

- clip ID, language-independent ordered row index, and source-audio SHA-256;
- requested sample count, actual sample count, and eligibility;
- the seven **absolute** selected native probabilities in declared mapping
  order, or equivalently exact selected log probabilities;
- optionally native 107-way top index/probability if that diagnostic is to be
  published; and
- no cached winner, maximum, conditional vector, selected mass, or summary as
  an authority—derive those from the retained raw seven values.

There are only 3,496 eligible requests and 24,472 selected values, so retaining
the derivable raw data is small relative to the current two-megabyte result.
It permits exact checks:

```text
selected_mass = sum(selected_absolute_probs)
conditional = selected_absolute_probs / selected_mass
winner_index = argmax(conditional)
prediction = language_codes[winner_index]
max_probability = conditional[winner_index]
```

If underflow makes ordinary probabilities undesirable, retain the exact seven
log values and derive with log-sum-exp. Whichever representation is selected
must be declared with dtype/serialization semantics and tested at extreme
values.

Hash three concepts separately:

1. `producer_identity_sha256` — process and all resolved inputs;
2. `prediction_payload_sha256` — exact ordered raw prediction records; and
3. `cache_payload_sha256` — producer identity plus raw output and observation
   envelope.

The physical file SHA-256 is an external publication fact; it cannot be a
field inside the bytes it names.

### 3. Validate and rederive on every reuse

A reuse must fail before any teacher value enters a result unless:

- schema and exact key set are recognized;
- the stored producer identity equals the current staged expected identity;
- BUG-17's independently derived input release, ordered rows, and all audio
  hashes match;
- the pinned Hub model files and exact ordered label map match;
- every prefix has exactly one record per expected clip in expected order;
- clip IDs/audio digests bind positions, so a count-preserving permutation
  fails;
- eligibility and null/non-null placement derive from actual sample counts;
- every raw value is finite and nonnegative and yields mass in `(0,1]` within
  declared tolerance;
- all payload digests recompute; and
- every published winner, maximum, confusion matrix, per-language metric,
  composite, and retained-mass aggregate is recomputed from raw values.

Prefer not storing summaries in the cache at all. If they are retained for
human inspection, equality with a pure rederivation must be a gate, never a
source of truth. Likewise, creation wall time must not be reported as if it
were measured by a later reuse invocation; name it
`producer_inference_wall_seconds` with the original invocation ID.

Strict source equality is appropriate here: a fresh teacher pass took 364.20
seconds, comfortably within the project budget. Supporting an older producer
through a compatibility declaration adds more risk than value. If such reuse
is ever allowed, the result must name and bind the **original** producer stage,
not attribute its output to the current consumer.

### 4. Bind the accepted artifact downstream

Before computing `run_id`, add at least these values to
`experiment_identity`:

```text
teacher_prediction_producer_identity_sha256
teacher_prediction_payload_sha256
accepted_teacher_cache_payload_sha256
```

The result's teacher summary must derive from that accepted payload. Changing
one otherwise valid prediction must therefore change both the prediction
digest and experiment run ID. Changing only a cached summary must fail because
the summary rederivation differs.

Bind the exact runtime object within the experiment identity as well, rather
than storing package versions only beside it. This is required independently
for student scoring and is naturally supplied by BUG-16's staged launcher.

## Required regressions

Use a tiny deterministic fixture for unit tests and one real 700-row offline
reuse test. No test needs repeated ECAPA inference except the final publication
run.

| Mutation / case | Required outcome |
|---|---|
| Change `evaluate_teacher`, `label_indices`, an imported helper, or package initializer | Producer mismatch; cache rejected before use. |
| Change `uv.lock`, Python/SpeechBrain/Torch identity, device, threads, or declared numerical recipe | Producer mismatch; fail closed. |
| Reorder project languages or teacher indices while preserving widths | Mapping mismatch; reject. |
| Change `label_encoder.txt` or another consumed model file | Model artifact mismatch; reject. |
| Change BUG-17 release lock, manifest record order, clip/audio hash, or prefix samples | Input mismatch; reject. |
| Permute 700 rows while retaining every value and count | Clip/order binding mismatch; reject. |
| Wrong null placement, duplicate/missing prefix row, unknown label, NaN/Inf, negative value, zero mass, or mass over tolerance | Structural/numeric validator rejects. |
| Change a cached winner/max/summary and recompute its self-hash | Pure rederivation rejects or ignores the redundant field. |
| Change valid-looking raw probabilities and recompute all local self-hashes | Accepted prediction digest and downstream run ID must change; the old run ID is impossible. |
| Generate once and reuse under the identical staged producer/input | Same producer/prediction digests and exactly equal recomputed teacher metrics. |
| Reuse with network disabled and the exact verified Hub snapshot present | Same semantic result; proves the cache does not silently resolve `main`. |
| Kill publication before the final replace | Previous complete cache remains readable; no mixed generation. |

The valid-looking-probability test needs precise wording. An unsigned local
artifact cannot prove authenticity against an active editor who can forge all
metadata. The required local guarantee is that such bytes cannot retain the
old run identity or bypass semantic rederivation. If adversarial authenticity
is later required, add a trusted signature/attestation or recompute the
teacher; do not claim that another self-hash solves it.

## One publication experiment

After BUG-16 and BUG-17 land:

1. preserve schema 1 and result `90d51177…b397` as historical evidence;
2. generate one schema-2 cache in the immutable staged child from the exact
   independently locked 700-row input;
3. run a second offline consumer against that cache and require identical
   producer/prediction digests and rederived summaries;
4. require all 3,496 eligibility outcomes, winners, conditional maxima,
   selected masses, and aggregate metrics to be finite and derivable;
5. compare every historical winner/max and all teacher metrics with schema 1,
   reporting exact counts and maximum probability differences; and
6. publish a separately named schema-2 experiment result whose run ID binds
   the accepted producer and prediction digests.

Expected direction: no teacher-control change. Exact parity is **unverified**;
if it fails, retain both artifacts and diagnose source/runtime/mapping/input
differences rather than overwriting history. Regardless of parity, do not
reopen the already-rejected student checkpoint promotion unless a separate
predeclared student criterion changes.

## Bottom line

The pinned ECAPA checkpoint is a verified dependency. The reusable prediction
JSON is a different artifact and needs its own generation lineage. Bind the
executed staged producer, runtime, mapping, inference recipe, and exact input;
retain derivable raw outputs; rederive every summary; and include the accepted
prediction digest in the experiment identity. That closes BUG-18 for stale and
accidental reuse without pretending an unsigned local cache is a cryptographic
attestation.
